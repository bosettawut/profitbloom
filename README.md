# ProfitBloom

ระบบคำนวณต้นทุน–กำไร และออกใบเสนอราคา สำหรับธุรกิจจัดดอกไม้/จัดงาน

ส่งมอบงาน / เจ้าของใหม่: อ่าน [HANDOVER.md](HANDOVER.md) ก่อน

- **Frontend:** React + Vite + Tailwind (ดีไซน์จาก Figma Make)
- **Backend:** Node.js + Express, ฐานข้อมูล PostgreSQL ผ่าน `pg` — บนเครื่องใช้ PostgreSQL ในเครื่อง, บน Vercel ใช้ [Supabase](https://supabase.com) (สิงคโปร์)
- **Login:** อีเมล + รหัสผ่าน (scrypt hash), session cookie แบบ httpOnly, ลืมรหัสผ่านผ่านลิงก์ทางอีเมล

ต้องใช้ Node.js 22.13 ขึ้นไป และ PostgreSQL 14 ขึ้นไป

## รันบนเครื่อง (development)

```bash
npm install
createdb profitbloom     # ครั้งแรกครั้งเดียว
npm run dev
```

เปิด http://localhost:5173 แล้วสมัครสมาชิกได้เลย
(`npm run dev` รันทั้ง API ที่พอร์ต 3001 และหน้าเว็บที่พอร์ต 5173 โดย Vite ส่งต่อ `/api` ไปที่ API)

ถ้าต้องการตั้งค่าเองบนเครื่อง (เปลี่ยนพอร์ต, ส่งอีเมลจริง, ชี้ฐานข้อมูลอื่น) คัดลอก `.env.example` เป็น `.env` แล้วแก้ค่าในนั้น `npm run dev` จะอ่านไฟล์นี้ให้เอง ค่าที่พิมพ์นำหน้าคำสั่งมีผลเหนือค่าในไฟล์ ไฟล์ `.env` ไม่ถูก commit และระบบจริงบน Vercel ไม่ใช้ไฟล์นี้

ข้อมูลเก็บในฐานข้อมูล `profitbloom` ของ PostgreSQL บนเครื่อง (ตารางถูกสร้างให้อัตโนมัติ) ถ้าต้องการเริ่มใหม่ทั้งหมด: `dropdb profitbloom && createdb profitbloom`
ถ้า PostgreSQL ไม่ได้อยู่ที่ `localhost:5432` ให้กำหนด `DATABASE_URL` เช่น `postgresql://user:pass@host:5432/profitbloom`

(ร้านที่ถูกระงับจะถูกออกจากระบบทันทีและ login ไม่ได้ ข้อมูลยังอยู่ครบ)

## Login และรหัสผ่าน

- **ลืมรหัสผ่าน:** หน้า Login → "ลืมรหัสผ่าน?" → ระบบส่งลิงก์ทางอีเมล ลิงก์ใช้ได้ครั้งเดียว หมดอายุใน 1 ชั่วโมง และขอได้ไม่เกิน 3 ฉบับต่ออีเมลใน 15 นาที ระบบตอบเหมือนกันไม่ว่าอีเมลนั้นจะมีบัญชีหรือไม่
- **ตั้งรหัสใหม่ / เปลี่ยนรหัสในหน้าตั้งค่า:** เครื่องอื่นที่ login ค้างไว้ถูกออกจากระบบ
- **ออกจากระบบทุกเครื่อง:** ปุ่มในหน้าตั้งค่า (รวมเครื่องที่กดด้วย)
- **กันเดารหัสผ่าน:** ใส่รหัสผิด 10 ครั้งใน 15 นาทีจากเครือข่ายเดียวกัน หรือ 50 ครั้งต่อบัญชีจากทุกที่ จะถูกพัก 15 นาที นับในฐานข้อมูล จึงใช้ได้ผลบน Vercel
- **บนเครื่อง (development):** ยังไม่ได้ตั้ง `RESEND_API_KEY` อีเมลจะแสดงใน Terminal ของ API แทน คัดลอกลิงก์จากตรงนั้นได้เลย

## ลูกค้า (CRM)

- **รายชื่อลูกค้า** (`/app/customers`): เพิ่ม แก้ไข ลบ และค้นหาลูกค้า (ชื่อ เบอร์โทร อีเมล LINE ที่อยู่ หมายเหตุ) หน้าของลูกค้าแต่ละคนแสดงโปรเจ็กต์ ใบเสนอราคา และยอดซื้อรวม
- **ยอดซื้อรวม** นับเหมือนรายงาน คือราคาขายของโปรเจ็กต์ที่อนุมัติแล้วหรือเสร็จสิ้น
- **ผูกลูกค้ากับงาน:** ช่อง "ชื่อลูกค้า" ในโปรเจ็กต์และใบเสนอราคาเลือกจากรายชื่อได้ (เติมเบอร์โทรและอีเมลให้) หรือเพิ่มลูกค้าใหม่จากตรงนั้น ถ้าพิมพ์ชื่อเองโดยไม่เลือก ระบบจะจับคู่กับลูกค้าชื่อเดียวกัน (ไม่สนตัวพิมพ์เล็กใหญ่) หรือสร้างลูกค้าใหม่ให้ตอนบันทึก
- **ข้อมูลเดิม:** ชื่อลูกค้าที่เคยพิมพ์ไว้ในโปรเจ็กต์และใบเสนอราคาถูกสร้างเป็นลูกค้าและผูกให้อัตโนมัติ (ชื่อเดียวกันในร้านเดียวกันนับเป็นคนเดียว)
- **ลบลูกค้า:** โปรเจ็กต์และใบเสนอราคาของลูกค้ารายนั้นยังอยู่ครบ ชื่อยังอยู่บนเอกสาร เพียงแต่ไม่ผูกกับรายชื่อแล้ว
- เบอร์โทรและอีเมลบนโปรเจ็กต์/ใบเสนอราคาเป็นของเอกสารนั้นเอง แก้ข้อมูลลูกค้าภายหลังจะไม่ย้อนไปแก้เอกสารเก่า
- **เบอร์หรืออีเมลในงานต่างจากที่จำไว้กับลูกค้า:** ตอนบันทึกโปรเจ็กต์หรือใบเสนอราคา ระบบถามว่าจะ "อัปเดตข้อมูลลูกค้า" หรือ "ใช้กับงานนี้เท่านั้น" (งานบางงานติดต่อคนอื่น เช่น ออร์แกไนเซอร์) ถ้าลูกค้ายังไม่มีเบอร์หรืออีเมล ระบบเติมให้เลยโดยไม่ถาม และไม่ถามซ้ำเมื่อบันทึกเอกสารเดิมโดยไม่ได้แก้ข้อมูลติดต่อ
- **ตรวจเบอร์โทร:** ช่องเบอร์โทรทุกที่ (ลูกค้า โปรเจ็กต์ ใบเสนอราคา เบอร์ร้าน) ไม่บังคับกรอก แต่ถ้ากรอกต้องเป็นเบอร์ไทย 9–10 หลักขึ้นต้นด้วย 0 หรือเบอร์ต่างประเทศขึ้นต้นด้วย `+` จะเว้นวรรค ใส่ขีด วงเล็บ หรือ "ต่อ 12" ก็ได้ (กติกาอยู่ใน `shared/contact.js`) เบอร์ที่บันทึกไว้ก่อนมีการตรวจจะไม่ถูกบังคับแก้จนกว่าจะแก้ช่องนั้นเอง
- **ตรวจอีเมลลูกค้า:** ช่องอีเมลของลูกค้า โปรเจ็กต์ และใบเสนอราคา ไม่บังคับกรอก แต่ถ้ากรอกต้องเป็นรูปแบบ `name@example.com` ใช้หลักเดียวกับเบอร์โทร: อีเมลที่บันทึกไว้ก่อนแล้วจะไม่ถูกบังคับแก้

## ตารางโปรเจ็กต์และใบเสนอราคา

บนจอกว้างแสดงเป็นตาราง กดหัวคอลัมน์เพื่อเรียง (กดซ้ำเพื่อกลับทิศ) ค้นหา กรองตามสถานะและช่วงวันที่ (โปรเจ็กต์ใช้วันที่จัดงาน ใบเสนอราคาใช้วันที่สร้าง) และแบ่งหน้า 10/25/50 รายการ บนจอที่แคบกว่าและมือถือแสดงเป็นการ์ดพร้อมการค้นหา ตัวกรอง และการแบ่งหน้าเดียวกัน ส่วนที่ใช้ร่วมกันอยู่ใน `src/components/ListTools.tsx`

ตารางต้องใช้ที่กว้าง จึงแสดงตั้งแต่จอกว้าง 1200px ขึ้นไป (จุดเปลี่ยน `rows` ใน `@theme` ของ `src/styles/globals.css`) จอที่แคบกว่านั้นและมือถือแสดงเป็นการ์ด เรียงสองคอลัมน์ตั้งแต่ 1024px และเรียงลำดับได้จากตัวเลือก "ช่วงเวลาและการเรียง" (หน้าลูกค้าใช้กล่องเรียงลำดับข้างช่องค้นหา)

จอที่กว้างไม่ถึง 1536px ตารางจะย่อคอลัมน์เพื่อให้ช่องชื่อยังกว้างพออ่าน: ตารางโปรเจ็กต์และใบเสนอราคาไม่มีคอลัมน์รหัสและลูกค้า ทั้งสองอย่างอยู่ใต้ชื่องานในช่องเดียวกัน ส่วนตารางลูกค้าไม่มีคอลัมน์ LINE โดยอยู่ใต้เบอร์โทรแทน การเรียงตามรหัสหรือลูกค้ายังทำได้จาก "ช่วงเวลาและการเรียง" จอ 1536px ขึ้นไปมีครบทุกคอลัมน์

## เลขที่เอกสาร

- รูปแบบ `ตัวนำหน้า-ปี-ลำดับ` เช่น `QT-2026-013` ปีเป็น ค.ศ. นับตามเวลาไทย (เซิร์ฟเวอร์ใช้เวลา UTC จึงแปลงก่อน เอกสารที่สร้างหลังเที่ยงคืนวันที่ 1 ม.ค. เวลาไทยได้ปีใหม่ทันที)
- แต่ละร้าน (บัญชี) มีเลขรันของตัวเอง เริ่มที่ 001 แยกตามตัวนำหน้าและแยกปี: ใบเสนอราคา `QT` · โปรเจ็กต์ตามประเภทงาน `WD` งานแต่งงาน `EN` งานหมั้น `BD` งานวันเกิด `OR` งานบวช `OP` งานเปิดร้าน `EV` อื่น ๆ และโปรเจ็กต์ที่สร้างจากใบเสนอราคา
- เลขที่ออกไปแล้วไม่ถูกใช้ซ้ำ แม้เอกสารนั้นจะถูกลบ (แบบเดียวกับ FlowAccount) เพราะลูกค้าอาจถือเอกสารเลขนั้นอยู่ เลขล่าสุดที่ออกของแต่ละร้าน ตัวนำหน้า และปี เก็บในตาราง `doc_counters` (ขั้นฐานข้อมูลที่ 15) ส่วนเลขที่มีอยู่ในเอกสารก็นับด้วย เอกสารที่สร้างก่อนมีตารางนี้หรือย้ายมาจากระบบเดิมจึงไม่ถูกออกเลขซ้ำ (`nextCode` ใน `server/app.js`)

## ต้นทุนแบบหัวข้อ

ขั้น "ต้นทุนและราคา" ของโปรเจ็กต์แบ่งต้นทุนเป็นหัวข้อที่ร้านตั้งชื่อเอง (เช่น ซุ้มดอกไม้, ทีมงาน) แต่ละหัวข้อมีรายการย่อยและ Margin ของตัวเอง

- **ราคาขายของงาน** = ผลรวมราคาขายของทุกหัวข้อ (ต้นทุนหัวข้อ × (1 + markup ของหัวข้อ)) และ Margin รวมของงานคิดจากผลรวมนั้น
- **คำเตือนและคะแนนสุขภาพงาน** ดูที่ Margin รวมของงาน ไม่เตือนรายหัวข้อ
- **Margin / ราคาขายในการ์ด "ราคาเสนอ"** เป็นของทั้งงาน: แก้ Margin หรือราคาขาย จะขยับทุกหัวข้อตามสัดส่วนเดิม (แต่ละหัวข้อคงส่วนแบ่งของราคาขายไว้) ให้ทั้งงานได้ตามที่กรอก เช่น หัวข้อ 35% กับ 14% (รวม 29.3%) ตั้ง Margin รวมเป็น 35% จะได้ 40.3% กับ 21.0% หัวข้อที่ Margin เท่ากันอยู่แล้วจะเท่ากันต่อไป และไม่มีหัวข้อไหนถูกปรับลงต่ำกว่าต้นทุนของตัวเอง ถ้าลดจนหัวข้อหนึ่งถึงต้นทุนแล้ว หัวข้อที่เหลือจะรับส่วนต่างแทน
- **เงื่อนไขงาน** "ค่าแรงเจ้าของ" และ "ค่าเก็บงานและขนส่งกลับ" อ่านจากรายการในหมวด "ค่าแรงเจ้าของ" และ "เก็บงาน/ขนส่งกลับ" เอง หรือจากชื่อรายการไม่ว่าจะอยู่หมวดไหน (ชื่อมีคำว่า "ค่าแรงเจ้าของ" · ชื่อมีคำว่า "เก็บงาน" หรือ "ขนส่งกลับ") ต้องมียอดมากกว่า 0 จึงนับว่าใส่แล้ว ถ้ามีรายการแต่ยอดเป็น 0 การ์ดจะขึ้น "ยังไม่ใส่ราคา" ไม่ต้องติ๊กแยก งานเก่าที่เคยติ๊ก "ใส่แล้ว" ไว้ยังนับว่าใส่แล้ว
- **หมวดต้นทุนของร้าน:** หน้าตั้งค่า → การ์ด "หมวดต้นทุน" เพิ่ม เปลี่ยนชื่อ และลบหมวดของร้านเองได้ (สูงสุด 30 หมวด ชื่อห้ามซ้ำ) หมวดมาตรฐาน 7 หมวดแก้ไม่ได้ เพราะ "ค่าแรงเจ้าของ" กับ "เก็บงาน/ขนส่งกลับ" ใช้ตอบเงื่อนไขงาน ลบหมวดแล้วรายการต้นทุนที่ใช้หมวดนั้นจะย้ายไป "อื่น ๆ" (ตาราง `cost_categories`, รายการต้นทุนอ้างถึงหมวดของร้านเป็น `c<id>`)
- **ใบเสนอราคาที่ลูกค้าตกลงแล้ว → โปรเจ็กต์:** ใบเสนอราคาที่สร้างเดี่ยว ๆ (ไม่ได้มาจากโปรเจ็กต์) เมื่อเปลี่ยนเป็น "อนุมัติแล้ว" ระบบถามว่าจะสร้างโปรเจ็กต์แล้วไปใส่ต้นทุนเลยไหม (หน้าใบเสนอราคามีปุ่ม "สร้างโปรเจ็กต์และใส่ต้นทุน" ไว้กดทีหลัง) โปรเจ็กต์ได้ข้อมูลงานและรายการจากใบเสนอราคา ราคาขายยึดตามยอดหลังส่วนลดก่อน VAT (`projects.agreed_price`) แก้ไม่ได้ Margin คำนวณจากต้นทุนที่กรอก ถ้าต้นทุนเกินราคาจะแสดงเป็นขาดทุน งานที่ยังไม่ใส่ต้นทุนจะไม่นับในรายงานยอดขายและยอดซื้อของลูกค้า และหน้ารายงานจะแจ้งว่ามีกี่งานที่รออยู่ (`POST /api/quotes/:id/project`)
- **เงินสดที่ต้องสำรอง** = ต้นทุนทั้งหมด − มัดจำ ไม่มีช่อง "จ่ายก่อนงาน" รายรายการแล้ว และไม่มีคำเตือนเรื่องมัดจำต่ำกว่าเงินจ่ายก่อนงาน
- **งานที่มีอยู่เดิม** ทุกรายการถูกย้ายเข้าหัวข้อเดียวชื่อ "รายการต้นทุน" ที่ markup เดิมของงาน ราคาจึงเท่าเดิม
- ค่าใช้จ่ายนอกแผน (ขั้นติดตามต้นทุนจริง) ไม่อยู่ในหัวข้อและไม่นับเป็นราคาขาย
- **โปรเจ็กต์ใหม่** เปิดมามี 2 หัวข้อ หัวข้อละ 4 แถวว่าง ช่องชื่อรายการมีคำใบ้สีเทา (โอเอซิส / ค่าแรง / ค่าขนส่ง / กุหลาบขาว) แถวที่ไม่ได้กรอก และหัวข้อที่ไม่มีทั้งชื่อและรายการ จะไม่ถูกบันทึก
- **หมวดของรายการ** ไม่ถูกเลือกให้ล่วงหน้า ช่องขึ้น "เลือกหมวด" ให้ร้านเลือกเอง รายการที่กรอกชื่อหรือราคาแล้วแต่ยังไม่เลือกหมวด ช่องหมวดจะเป็นสีแดง และตอนกด "ถัดไป" (ขั้นต้นทุนของฟอร์มสร้างโปรเจ็กต์) หรือ "บันทึก" (หน้างาน) จะมี pop up บอกรายการที่ยังไม่ได้เลือก ให้เลือกระหว่าง "กลับไปเลือกหมวด" กับ "ไปต่อ" / "บันทึกเลย" รายการที่ยังไม่เลือกเก็บหมวดเป็นค่าว่าง และนับเป็น "อื่น ๆ" ในการคำนวณ
- **หน่วยของรายการ** (เช่น ดอก, กำ, คน, เที่ยว) พิมพ์เองได้ ไม่บังคับ ยาวไม่เกิน 30 ตัวอักษร ไม่มีผลกับการคำนวณ และไม่แสดงในใบเสนอราคา
- **ปุ่ม "ยังไม่ใส่ · เพิ่มรายการ"** ของค่าแรงเจ้าของ และค่าเก็บงานและขนส่งกลับ (การ์ด "เงื่อนไขงาน") จะถามก่อนว่าจะเพิ่มรายการไว้ใต้หัวข้อไหน หรือสร้างหัวข้อใหม่ ซึ่งต้องตั้งชื่อหัวข้อในกล่องเดียวกัน
- **เทียบกับงบลูกค้า** เมื่อกรอก "งบที่ลูกค้าเสนอ" และงานมีราคาขายแล้ว ใต้ช่องงบจะบอกว่า "เกินงบลูกค้า ฿…" (แดง) "พอดีงบลูกค้า" หรือ "อยู่ในงบลูกค้า เหลือ ฿…" (เขียว) เทียบจากราคาเสนอขายปัดเป็นบาทเต็ม (ยังไม่รวม VAT) คำเตือน "ราคาสูงกว่างบลูกค้า" ในเช็คสุขภาพงานใช้การเทียบเดียวกัน
- **ส่วนลดของหัวข้อ** แต่ละหัวข้อมีช่อง "ส่วนลด" หน้าช่อง Margin เลือกหน่วยเป็น % หรือบาท ลดจากราคาขายที่ Margin ของหัวข้อให้ (ราคาขายหัวข้อ = ต้นทุน × (1 + markup) − ส่วนลด) เช่น ต้นทุน 10,000 Margin 35% ราคา 15,385 ลด 10% เหลือ 13,846 ช่อง Margin ของหัวข้อยังเป็นค่าก่อนลด บรรทัดสรุปท้ายหัวข้อบอกยอดที่ลด ราคาหลังลด และ Margin หลังลด (ขึ้นสีแดง "ต่ำกว่าทุน" ถ้าลดจนต่ำกว่าต้นทุน) Margin และราคาขายรวมของงาน มัดจำ งบลูกค้า เช็คสุขภาพงาน และราคาที่ล็อกในใบเสนอราคา คิดจากราคาหลังลดทั้งหมด แก้ Margin หรือราคาขายรวม ระบบขยับ Margin ของหัวข้อโดยส่วนลดคงเดิม งานที่ยึดราคาตามใบเสนอราคาที่ลูกค้าตกลงแล้วใช้ส่วนลดไม่ได้
- **ใบเสนอราคาของงาน** มีหัวข้อละหนึ่งบรรทัด: รายละเอียดคือชื่อหัวข้อ (หัวข้อที่ยังไม่มีชื่อเป็น "หัวข้อที่ N") จำนวน 1 ราคาคือราคาขายของหัวข้อ ซึ่งรวม Margin และหักส่วนลดของหัวข้อแล้ว ลูกค้าจึงเห็นหัวข้อกับราคา ไม่เห็นรายการต้นทุนข้างในและไม่เห็นบรรทัดส่วนลดแยก หัวข้อที่ยังไม่มีต้นทุนไม่อยู่ในใบ ราคาของทุกหัวข้อปัดเป็นบาทเต็มร่วมกันให้รวมแล้วเท่าราคาของงาน โดยหัวข้อที่เป็นบาทเต็มอยู่แล้วไม่ถูกขยับ (`quoteLinesFromJob` ใน `shared/quote-math.js`) บรรทัดเหล่านี้แก้ในใบไม่ได้ ดูหัวข้อ "งานกับใบเสนอราคาผูกกัน" ด้านล่าง
- **มัดจำเป็นบาท** การ์ด "ราคาเสนอ" แสดง "มัดจำ (30%) ฿…" ใต้ราคาเสนอขาย = ราคาเสนอขาย × มัดจำ% (ยังไม่รวม VAT) ไม่แสดงเมื่อมัดจำเป็น 0

API: โปรเจ็กต์มี `costGroups: [{ id, name, markup, discountType, discount }]` (`discountType` เป็น `percent` หรือ `baht` · `discount` 0 = ไม่ลด) และแต่ละ `costItems[]` มี `groupId` กับ `unit` (หน่วย ไม่บังคับ) และ `category` ที่เป็นค่าว่างได้เมื่อยังไม่เลือกหมวด ส่งหัวข้อใหม่ด้วย id ชั่วคราว (เช่นเลขติดลบ) แล้วอ้างจาก `groupId` ได้ `profitMargin` ของโปรเจ็กต์คือ markup รวมที่เซิร์ฟเวอร์คำนวณให้ตอนบันทึก ถ้าส่ง `profitMargin` โดยไม่ส่ง `costGroups` จะตั้งทุกหัวข้อเท่ากัน

## รายงานยอดขาย

หน้า "รายงาน" มีส่วน "รายงานยอดขาย": ยอดขาย ต้นทุน กำไร และ Margin ของโปรเจ็กต์ที่อนุมัติแล้วหรือเสร็จสิ้น เลือกช่วงวันที่ได้ (นับตามวันที่จัดงาน ถ้างานไม่มีวันที่จัดงานจะใช้วันที่สร้าง) ดูแบบรายเดือนหรือรายลูกค้า และกด "ส่งออก Excel" ได้ไฟล์ .xlsx ที่มี 4 แผ่น: รายเดือน รายลูกค้า รายการงาน และข้อมูลรายงาน ตัวเลขในไฟล์เป็นตัวเลขจริง ใช้สูตรรวมต่อใน Excel ได้ ตัวสร้างไฟล์อยู่ที่ `src/lib/xlsx.ts`

## ราคาในใบเสนอราคา

สูตรอยู่ที่ `shared/quote-math.js` ไฟล์เดียว ใช้ทั้งฝั่ง API หน้าเว็บ และ PDF ตัวเลขจึงตรงกันเสมอ

- **การปัดเศษ (เลือกได้ทีละรายการ):** ในตารางรายการ แต่ละบรรทัดมีช่องติ๊ก "ปัด" ถ้าติ๊ก ยอดของบรรทัดนั้น (จำนวน × ราคาต่อหน่วย) จะปัดขึ้นเป็นบาทเต็มทันทีที่มีเศษ เช่น 99.01 เป็น 100 ถ้าไม่ติ๊ก ยอดคิดถึงสตางค์ (ครึ่งสตางค์ปัดขึ้น) รายการใหม่ติ๊กไว้ให้ก่อน ส่วนลด VAT และยอดรวมคิดถึงสตางค์เสมอ ไม่ปัด ทศนิยมจะแสดงก็ต่อเมื่อมียอดใดในใบนั้นมีสตางค์ ใบเสนอราคาที่สร้างก่อนมีตัวเลือกนี้ยังใช้กติกาเดิม (ทุกยอดปัดเป็นบาทเต็ม ตั้งแต่ 50 สตางค์ปัดขึ้น) ยอดจึงไม่เปลี่ยน จนกว่าจะกด "เลือกปัดทีละรายการ" ในใบนั้นแล้วบันทึก
- **ปุ่มบันทึกใบเสนอราคา** (ทั้งด้านบนและด้านล่างบนมือถือ) กดได้เมื่อใบยังไม่เคยบันทึก หรือเมื่อมีอะไรต่างจากที่บันทึกไว้ ถ้าบันทึกแล้วและยังไม่ได้แก้ ปุ่มจะซีดและกดไม่ได้ (ชี้แล้วขึ้น "บันทึกแล้ว ยังไม่มีการแก้ไข") แก้แล้วเปลี่ยนกลับเป็นค่าเดิม ปุ่มก็ซีดอีกครั้ง
- **หน้าสร้าง/แก้ไขใบเสนอราคา** จัดวางเป็นการ์ดเดียว: หัวหน้ามีปุ่ม "ปิดหน้าต่าง" กับ "บันทึกใบเสนอราคา" (บนจอคอมค้างอยู่ด้านบนตอนเลื่อน) · ข้อมูลลูกค้าอยู่ซ้าย ยอดรวมตัวใหญ่ ปุ่มดูตัวอย่าง/ดาวน์โหลด PDF และวันที่อยู่ขวา · ชื่อโปรเจ็กต์กับตัวเลือก VAT · ตารางรายการมีเลขลำดับ ปุ่ม "เพิ่มรายการ" อยู่ใต้ตาราง · หมายเหตุอยู่ซ้าย สรุปยอดอยู่ขวา โดยช่องส่วนลด อัตรา VAT และหัก ณ ที่จ่ายอยู่ในสรุปยอด บนมือถือเรียงเป็นคอลัมน์เดียวและปุ่มบันทึกอยู่ท้ายฟอร์ม
- **ช่องเพิ่มเติมของใบเสนอราคา** (ไม่บังคับทุกช่อง): ที่อยู่ลูกค้า เลขประจำตัวผู้เสียภาษี และสำนักงาน/สาขา (พิมพ์ใต้ชื่อลูกค้าในเอกสาร) · เลขที่อ้างอิง เช่น เลขใบสั่งซื้อของลูกค้า · เครดิต (วัน) ซึ่งคิดวันครบกำหนดชำระ = วันที่จัดงาน + จำนวนวัน · หน่วยของแต่ละรายการ (พิมพ์ต่อท้ายจำนวน เช่น "200 ดอก") · โน้ตภายในที่ไม่พิมพ์ในเอกสาร เลือกลูกค้าจากรายชื่อ (หรือสร้างใบเสนอราคาจากงานของลูกค้ารายนั้น) ระบบเติมที่อยู่จากระเบียนลูกค้า และเติมเลขผู้เสียภาษีกับสาขาจากใบเสนอราคาล่าสุดของลูกค้ารายนั้นให้ โปรเจ็กต์ที่สร้างจากใบเสนอราคาได้หน่วยของแต่ละบรรทัดไปเป็นหน่วยของรายการต้นทุน
- **ตารางรายการของใบเสนอราคา** แสดงเป็นตารางบนจอกว้างตั้งแต่ 1280px ขึ้นไป จอที่แคบกว่านั้นแต่ละรายการเป็นการ์ด
- **VAT 3 แบบ ต่อใบเสนอราคา:** บวก VAT เพิ่มจากราคา / ราคารวม VAT แล้ว (ถอด VAT ออกมาแสดง ลูกค้าจ่ายเท่าเดิม) / ไม่มี VAT ร้านตั้งค่าเริ่มต้นได้ในหน้าตั้งค่า
- **หัก ณ ที่จ่าย (เลือกได้รายใบ):** ช่อง "หัก ณ ที่จ่าย (%)" ในการ์ด "การคำนวณเพิ่มเติม" ใส่ 0 คือไม่หัก (ค่าเริ่มต้น) ยอดหักคิดจากยอดก่อน VAT หลังหักส่วนลด และคิดถึงสตางค์ สรุปการเงิน เอกสารตัวอย่าง และ PDF จะมีบรรทัด "หัก ณ ที่จ่าย" และ "ยอดชำระ" (ยอดรวมสุทธิ ลบ ยอดหัก) ต่อท้ายยอดรวมสุทธิ ยอดรวมสุทธิ ยอดขายในรายงาน และราคาที่ล็อกไม่เปลี่ยน ระบบคำนวณตามอัตราที่กรอก ไม่ได้ตัดสินว่าใบไหนต้องหัก
- **งานกับใบเสนอราคาผูกกัน:** งานหนึ่งมีใบเสนอราคาที่ผูกไว้หนึ่งใบ รายการและราคาในใบคือของงาน (หัวข้อละบรรทัด) แก้ในใบไม่ได้ และไม่มีช่องส่วนลดในใบ เพราะส่วนลดให้ที่หัวข้อในงาน
  - ในใบมีแถบ "รายการและราคามาจากโปรเจ็กต์" พร้อมปุ่ม **กลับไปแก้โปรเจ็กต์** ซึ่งเปิดงานที่ขั้นต้นทุนและราคา ส่วนในหน้างาน ปุ่ม "สร้างใบเสนอราคา" จะเป็น **เปิดใบเสนอราคา** เมื่องานมีใบแล้ว และสร้างใบที่สองให้งานเดียวกันไม่ได้
  - บันทึกงานเมื่อไร ใบจะเปลี่ยนตามทันที (รายการ ราคา และยอดรวม) ข้อความยืนยันจะบอกว่าใบไหนเปลี่ยน
  - **ปุ่มบันทึกในหน้างาน:** เมื่อมีการแก้ที่ยังไม่บันทึก หัวหน้างานจะมีปุ่ม **ยกเลิกการแก้ไข** และปุ่มบันทึกสีหลักข้างปุ่ม "เปิดใบเสนอราคา" (ซึ่งกลายเป็นปุ่มรองชั่วคราว) ชื่อปุ่มคือ **บันทึกและอัปเดตใบเสนอราคา** เมื่องานมีใบที่ผูกไว้ ส่วนงานที่ยังไม่มีใบคือ **บันทึกการเปลี่ยนแปลง** แถบด้านล่างจอ "มีการแก้ไขที่ยังไม่บันทึก" มีปุ่มชื่อเดียวกันสีม่วง บนมือถือแถบกว้างเต็มจอ ปุ่มยกเลิกย่อเป็น "ยกเลิก" และจอแคบกว่า 360px ปุ่มบันทึกไม่มีไอคอน เพื่อให้ชื่อปุ่มอยู่บรรทัดเดียว
  - ถ้าใบ **ส่งแล้ว** หรือ **อนุมัติแล้ว** และการบันทึกครั้งนั้นจะทำให้ใบเปลี่ยน ระบบจะถามก่อนว่าจะแก้จริงหรือไม่ พร้อมบอกราคาเดิมและราคาใหม่ ตอบ "ไม่แก้" จะไม่มีอะไรถูกบันทึก ตอบ "แก้และอัปเดตใบเสนอราคา" งานถูกบันทึกและใบเปลี่ยนตาม สถานะของใบคงเดิม การบันทึกที่ไม่กระทบสิ่งที่อยู่ในใบ (หมายเหตุ สถานะ ต้นทุนจริง ค่าใช้จ่ายนอกแผน) ไม่ถูกถาม (ฝั่ง API: `PUT /api/projects/:id` ตอบ 409 พร้อม `code: 'quote_change'` จนกว่าจะส่ง `confirmQuoteChange: true`)
  - ใบที่ลูกค้า **ปฏิเสธ**: แก้ราคาที่งานแล้วบันทึก ใบเดิม (เลขเดิม) เปลี่ยนตามโดยไม่ถามยืนยัน แล้วโปรเจ็กต์กลับเป็น **สร้างใบเสนอราคาแล้ว** และใบกลับเป็น **ร่าง** ข้อความหลังบันทึกบอกว่ารอส่งใหม่ เมื่อส่งให้ลูกค้าอีกครั้งก็เปลี่ยนเป็น "รอการอนุมัติ" (ใบเป็น "ส่งแล้ว") ตามปกติ การบันทึกที่ไม่เปลี่ยนใบ (เช่น หมายเหตุ) สถานะยังเป็นลูกค้าปฏิเสธ ปุ่ม "อัปเดตใบนี้ตามโปรเจ็กต์" ในใบที่ถูกปฏิเสธก็ทำแบบเดียวกัน
  - สิ่งที่ยังแก้ในใบได้คือของใบเอง: ข้อมูลลูกค้า วันที่ เครดิต เลขที่อ้างอิง VAT หัก ณ ที่จ่าย หมายเหตุ โน้ตภายใน และสถานะ
  - ลบงาน: ใบยังอยู่พร้อมรายการล่าสุด และกลับเป็นใบธรรมดาที่แก้รายการได้ ลบใบ: งานสร้างใบใหม่ได้
  - ใบเปลี่ยนก็ต่อเมื่อการบันทึกงานครั้งนั้นเปลี่ยนสิ่งที่งานให้กับใบ (ชื่อหัวข้อ หัวข้อที่มีต้นทุน หรือราคา) การบันทึกอย่างอื่นไม่แตะใบเลย
  - งานที่มีใบเสนอราคาหลายใบอยู่ก่อนแล้ว: ใบล่าสุดเป็นใบที่ผูก ใบเก่ากว่าเป็นสำเนาเดิม ไม่เปลี่ยนตาม (ขั้นฐานข้อมูลที่ 14 และสคริปต์ย้ายข้อมูลจากระบบเดิมใช้กติกาเดียวกัน คือ `TIE_QUOTES` ใน `server/db.js`)
  - ใบที่ผูกไว้แต่รายการยังไม่ตรงกับงาน เพราะสร้างไว้ก่อนมีระบบนี้ จะยังเก็บรายการเดิมไว้ ในใบมีข้อความบอกพร้อมราคาของงานตอนนี้ และปุ่ม **อัปเดตใบนี้ตามโปรเจ็กต์** ให้กดเมื่อต้องการ (`POST /api/quotes/:id/sync` ถามยืนยันแบบเดียวกันถ้าใบส่งแล้วหรืออนุมัติแล้ว) การกรอกต้นทุนจริงหรือปิดงานเก่าจึงไม่ไปเขียนทับใบเก่า ส่วนถ้าแก้ราคาของงานนั้นจริง ใบจะเปลี่ยนตามเหมือนใบอื่น
- **ล็อกราคา (เฉพาะงานที่สร้างจากใบเสนอราคา):** งานที่สร้างจากใบเสนอราคาที่ลูกค้าตกลงแล้วมีราคาตายตัวตามใบนั้น ใบเสนอราคาของงานแบบนี้ไม่ตามงาน แต่ถูกล็อกไว้ที่ราคาที่ตกลง: แก้รายการได้ แต่ยอดรายการหลังหักส่วนลด (ก่อนบวก VAT) ต้องเท่าราคาที่ล็อกจึงจะบันทึกได้ ปุ่ม "ปรับส่วนต่างอัตโนมัติ" จะแก้ราคาบรรทัดเดียวให้ยอดตรง ในหน้างานแบบนี้ ปุ่มก็เป็น "เปิดใบเสนอราคา" เหมือนกัน พาไปใบที่สร้างงานนี้ขึ้นมา (ถ้ามีหลายใบ คือใบล่าสุด) ถ้าลบใบเสนอราคาของงานนี้หมด ปุ่มจะกลับเป็น "สร้างใบเสนอราคา" และใบใหม่ยังถูกล็อกไว้ที่ราคาที่ตกลง ส่วนในใบแบบนี้ (และใบเก่าที่อ้างถึงงานแต่ไม่ได้ผูก) มีปุ่ม **เปิดโปรเจ็กต์** ข้างปุ่มดูตัวอย่างและดาวน์โหลด PDF ซึ่งเปิดหน้างานนั้น ชื่อปุ่มต่างจาก "กลับไปแก้โปรเจ็กต์" ของใบที่ผูก เพราะแก้ที่งานแล้วใบแบบนี้ไม่เปลี่ยนตาม

## ขึ้นใช้งานจริง (production)

### Vercel + Supabase (สิงคโปร์)

- หน้าเว็บ build ด้วย `vite build` → `dist/`, API ทั้งหมดวิ่งผ่าน serverless function `api/index.js` ที่ region `sin1` (ดู `vercel.json`)
- ฐานข้อมูลอยู่บน Supabase region Southeast Asia (Singapore) — ตั้งค่า Environment Variables ใน Vercel:

| ตัวแปร | ความหมาย |
| --- | --- |
| `DATABASE_URL` | connection string แบบ **Transaction pooler** (พอร์ต 6543) จาก Supabase → Connect |
| `DATABASE_CA_CERT` | (แนะนำ) ใบรับรองจาก Supabase → Database → SSL Configuration เพื่อให้ตรวจสอบตัวตนของเซิร์ฟเวอร์ฐานข้อมูล |
| `RESEND_API_KEY` | API key ของ [Resend](https://resend.com) สำหรับส่งอีเมลตั้งรหัสผ่านใหม่ — ถ้าไม่ตั้ง อีเมลจะไม่ถูกส่ง |
| `MAIL_FROM` | ผู้ส่งอีเมล เช่น `ProfitBloom <no-reply@โดเมนของร้าน>` (ต้องยืนยันโดเมนใน Resend ก่อน) |
| `APP_URL` | ที่อยู่เว็บจริง เช่น `https://app.โดเมนของร้าน` ใช้สร้างลิงก์ในอีเมล (ถ้าไม่ตั้งจะใช้โดเมน production ของ Vercel) |

ตารางถูกสร้างและอัปเดตให้อัตโนมัติตอนเรียก API ครั้งแรก (ดู `MIGRATIONS` ใน `server/db.js`) ทุกตารางเปิด Row Level Security ไว้ เพื่อไม่ให้เข้าถึงผ่าน REST API ของ Supabase ได้
ตั้งแอดมินบนฐานข้อมูลจริง: `DATABASE_URL=... npm run make-admin -- อีเมล`

### ย้ายข้อมูลจากระบบเดิม (Turso / SQLite)

```bash
# ต้นทาง: TURSO_DATABASE_URL + TURSO_AUTH_TOKEN (หรือ SQLITE_FILE=ไฟล์.db)   ปลายทาง: DATABASE_URL
npm run migrate-data -- --dry-run   # ดูจำนวนแถวก่อน ยังไม่เขียน
npm run migrate-data                # ย้ายจริง (หยุดถ้าปลายทางมีข้อมูลแล้ว)
```

ย้ายทั้งหมดในครั้งเดียว ถ้าพลาดกลางทางจะไม่มีอะไรถูกเขียน และตรวจจำนวนแถวกับยอดเงินให้ก่อนยืนยัน บัญชี รหัสผ่าน และการ login ค้างไว้ของร้านใช้ต่อได้เลย สร้างรายชื่อลูกค้าจากชื่อในโปรเจ็กต์กับใบเสนอราคาให้ด้วย และจัดต้นทุนของแต่ละงานเข้าหัวข้อ "รายการต้นทุน"

ต้องเปิดผ่าน **HTTPS** เพราะ cookie ตั้งค่า `Secure` ในโหมด production

## ระบบช่วยตัดสินใจก่อนรับงาน (ตาม Product Vision)

ทุกตัวเลขมาจาก `src/lib/decision.ts` ที่เดียว (กติกาธุรกิจ + การคำนวณ ไม่ใช้ AI) และมี unit test เทียบกับตัวอย่างใน Product Vision ทุกสไลด์

| ส่วน | อยู่ที่ |
| --- | --- |
| Can I Take This Job? (เช็คก่อนรับงาน) | เมนู "เช็คก่อนรับงาน" |
| Job Health Check (คะแนน 0–100) | งานแต่ละงาน ขั้นที่ 1 + หน้าหลัก + การ์ดโปรเจ็กต์ |
| Quote Health Check | ขึ้นทุกครั้งก่อนสร้างใบเสนอราคาจากงาน |
| Scenario Simulator | งานแต่ละงาน ขั้นที่ 3 |
| Estimated vs Actual | งานแต่ละงาน ขั้นที่ 4 + หน้ารายงาน |
| Post-Event Review + Learning Loop | งานแต่ละงาน ขั้นที่ 5 → เตือนเผื่อต้นทุนในงานถัดไป |
| กติกาธุรกิจ (Margin เสี่ยง/ขั้นต่ำ/ที่ดี, มัดจำ, ค่าแรง, ค่ารถ, เกณฑ์ Labor Overrun) | ตั้งค่า → กติกาธุรกิจ |

**Margin = กำไร ÷ ราคาขาย** (ไม่ใช่กำไร ÷ ต้นทุน ซึ่งคือ markup) — ฐานข้อมูลเก็บเป็น markup (`cost_groups.markup` รายหัวข้อ และ `projects.profit_margin` ของทั้งงาน) แต่หน้าจอแสดงและรับค่าเป็น Margin

## การคำนวณ

- **ราคาขายของโปรเจ็กต์** = ผลรวมของ (ต้นทุนหัวข้อ × (1 + markup% ของหัวข้อ)) และ **Margin** = กำไร ÷ ราคาขาย
- **ยอดขาย/กำไรบน Dashboard และ Reports** นับเฉพาะโปรเจ็กต์ที่ "อนุมัติแล้ว" หรือ "เสร็จสิ้น" ตามเดือนของวันจัดงาน
- **อัตราความสำเร็จ** = (อนุมัติ + เสร็จสิ้น) ÷ (อนุมัติ + เสร็จสิ้น + ยกเลิก)
- **สถานะโปรเจ็กต์กับใบเสนอราคาผูกกันสองทาง** (เฉพาะใบที่หน้าโปรเจ็กต์เปิด คือใบที่ผูกกับงาน หรือใบที่สร้างงานนี้ขึ้นมา ใบเก่าที่ไม่ได้ผูกแล้วไม่มีผลกับสถานะโปรเจ็กต์) เปลี่ยนฝั่งไหน อีกฝั่งเปลี่ยนตาม:

  | ใบเสนอราคา | โปรเจ็กต์ |
  | --- | --- |
  | ร่าง | สร้างใบเสนอราคาแล้ว |
  | ส่งแล้ว | รอการอนุมัติ |
  | อนุมัติแล้ว | อนุมัติแล้ว |
  | ปฏิเสธ | ลูกค้าปฏิเสธ (แก้ราคาที่โปรเจ็กต์แล้วบันทึก ใบเดิมเปลี่ยนตาม เลขเดิม และทั้งสองกลับเป็น สร้างใบเสนอราคาแล้ว / ร่าง รอส่งใหม่) |
  | ยกเลิก | ยกเลิก |

  - ปิดงานเป็น **เสร็จสิ้น** ได้เมื่อโปรเจ็กต์ **อนุมัติแล้ว** (เมื่อมีระบบใบเสร็จ จะเปลี่ยนเป็น "มีใบเสร็จแล้ว") ใบเสนอราคายังเป็นอนุมัติแล้ว และระหว่างที่งานเสร็จสิ้นแล้ว เปลี่ยนสถานะใบเสนอราคาของงานไม่ได้ ต้องเปลี่ยนที่โปรเจ็กต์ก่อน
  - โปรเจ็กต์ที่มีใบเสนอราคาแล้ว เปลี่ยนกลับเป็น **ร่าง** ไม่ได้ ส่วนโปรเจ็กต์ที่ยังไม่มีใบ เลือกได้เฉพาะ ร่าง / อนุมัติแล้ว / เสร็จสิ้น (เมื่ออนุมัติแล้ว) / ยกเลิก
  - **ลบใบเสนอราคา** โปรเจ็กต์กลับเป็นร่าง (ยกเว้นงานที่เสร็จสิ้นหรือยกเลิกแล้ว) **ลบโปรเจ็กต์** ใบเสนอราคาของงานเป็น "ยกเลิก" (ใบที่ลูกค้าปฏิเสธคงไว้) และขึ้นแถบแดงในหน้าใบว่า "โปรเจ็กต์ … ของใบเสนอราคานี้ถูกลบแล้ว" ส่วนในหน้ารายการ ชื่องานเป็นสีแดงพร้อมบอกเลขโปรเจ็กต์ที่ถูกลบ (ขั้นฐานข้อมูลที่ 16 เก็บเลขนี้ไว้)
  - เปลี่ยนสถานะทั้งโปรเจ็กต์และใบเสนอราคาด้วยหน้าต่างเดียวกัน (`src/components/StatusDialog.tsx`): ไอคอน ชื่อ คำอธิบาย และสถานะที่เลือกไม่ได้จะซีดพร้อมบอกเหตุผล ใช้ในหน้ารายการโปรเจ็กต์ หน้าโปรเจ็กต์ (บันทึกพร้อมการแก้อื่นในหน้า) และหน้ารายการใบเสนอราคา
- **ใบเสนอราคา** ที่เลยวัน "ใช้ได้ถึง" และยังเป็นร่าง/ส่งแล้ว จะแสดงเป็น "หมดอายุ"
